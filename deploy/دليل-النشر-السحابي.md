# نشر النظام على السحابة — مجاناً

**النتيجة النهائية:** نظامك على `https://erp.ibrahimsaud.com` يعمل ٢٤ ساعة،
بياناته في قاعدة Supabase حقّك، وبدون أي اشتراك شهري.

**التكلفة:** ٠ ريال. خادم Oracle «Always Free» مجاني دائماً (ليس تجربة مؤقتة)،
وSupabase على الباقة المجانية (نظامك يحتاج ٧٩ ميجا من أصل ٥٠٠).

---

## لماذا لا GitHub؟

GitHub Pages يعرض ملفات ثابتة فقط، و‏Actions آلة بناء مؤقتة تنطفئ بعد انتهاء المهمة
(واستخدامها كخادم دائم مخالف لشروطه). النظام تطبيق بايثون يعمل باستمرار — يحتاج خادماً.
موقعك يبقى على GitHub كما هو؛ النظام فقط ينتقل للخادم.

---

## الخطوات

### ١) حساب Oracle Cloud (١٥ دقيقة)

1. سجّل في <https://signup.cloud.oracle.com>
2. **مهم — اختيار المنطقة:** اختر `Saudi Arabia Central (Jeddah)` أو `Germany Central (Frankfurt)`.
   لا يمكن تغييرها بعد التسجيل، والموارد المجانية تُعطى في هذه المنطقة فقط.
   اختر المنطقة الأقرب لمنطقة مشروع Supabase (كل ما قربت، كل ما صار النظام أسرع).
3. يطلب بطاقة للتحقق من الهوية — يخصم ريالاً واحداً ويرجّعه. موارد Always Free لا تُحاسَب.

### ٢) إنشاء الخادم

من لوحة Oracle ← **Compute** ← **Instances** ← **Create Instance**:

| الحقل | القيمة |
|---|---|
| الاسم | `isystem` |
| Image | **Canonical Ubuntu 24.04** |
| Shape | **Ampere VM.Standard.A1.Flex** — 4 OCPU / 24 GB |
| SSH keys | **Save private key** ← نزّل الملف واحتفظ به |

> لو ظهر `Out of capacity` للـ ARM، جرّب لاحقاً أو غيّر Availability Domain.

احفظ **Public IP address** الظاهر بعد الإنشاء.

### ٣) فتح المنافذ

في صفحة الخادم ← Subnet ← Security List ← **Add Ingress Rules**، أضف قاعدتين:

| Source CIDR | Protocol | Port |
|---|---|---|
| `0.0.0.0/0` | TCP | `80` |
| `0.0.0.0/0` | TCP | `443` |

### ٤) ربط النطاق

في Hostinger (حيث DNS نطاقك) أضف سجلاً:

| Type | Name | Points to |
|---|---|---|
| A | `erp` | عنوان IP الخادم |

### ٥) تجهيز Supabase

1. افتح مشروعك ← **SQL Editor** ← **New query**
2. افتح [`supabase-prepare.sql`](supabase-prepare.sql) وشغّل **كل دفعة وحدها** (خمس دفعات)
3. **غيّر كلمة المرور** في الدفعة الأولى قبل تشغيلها، واحفظها
4. الدفعة الأخيرة تعرض جدول تحقق: يفترض أن يكون
   «النظام يقدر ينشئ» = `true` للمخطّط `odoo`، و«anon يشوفه» = `false`

> **ليش دفعات منفصلة؟** Supabase يقطع الاتصال عند بعض عمليات الأدوار
> (مثل `GRANT` على دور جديد)، وتشغيل كل دفعة وحدها يحفظ ما نجح
> ولا يُلغى كله بسبب انقطاع واحد.
>
> **ملاحظة:** المخطّط يبقى مملوكاً لـ`postgres` — هذا طبيعي ولا يؤثر.
> النظام يملك جداوله التي ينشئها، وتوجيهه للمخطّط الصحيح يتم من الخادم
> عبر `PGOPTIONS` (مضبوط تلقائياً في سكربت النشر).

ثم من **Project Settings ← Database ← Connection string ← Session pooler**
انسخ اسم المضيف (مثل `aws-0-eu-central-1.pooler.supabase.com`) ومعرّف المشروع.

> **مهم:** استخدم **Session pooler** لا Transaction pooler — النظام يحتاج جلسة ثابتة.

### ٦) التثبيت (أمر واحد)

من جهازك، ادخل الخادم:

```bash
chmod 600 ~/Downloads/ssh-key-*.key
ssh -i ~/Downloads/ssh-key-*.key ubuntu@عنوان_الخادم
```

ثم على الخادم:

```bash
sudo apt update && sudo apt install -y git
git clone https://github.com/ibrahimsaud-255/ibrahimsaud-site.git
cd ibrahimsaud-site/deploy
cp env.example .env
nano .env          # عبّي بيانات Supabase والنطاق
bash oracle-setup.sh
```

السكربت يتكفّل بالباقي: المكتبات، سورس المحرّك، وحدة هويتك، تهيئة القاعدة
داخل المخطّط المعزول، خدمة دائمة، وشهادة HTTPS تلقائية.
المدة المتوقّعة: ٢٠–٣٠ دقيقة.

## بعد النشر

| الأمر | الوظيفة |
|---|---|
| `sudo systemctl status isystem` | حالة النظام |
| `sudo systemctl restart isystem` | إعادة تشغيل |
| `sudo tail -f /opt/isystem/data/isystem.log` | السجل المباشر |
| `cd ~/ibrahimsaud-site && git pull && bash deploy/oracle-setup.sh` | تحديث الهوية بعد تعديلها |

الدخول بنفس حساب النظام المحلي (في `.odoo-secrets`).

## الأمان — ما تم ضبطه

- بيانات النظام في مخطّط `odoo` **معزول**، غير مكشوف عبر واجهة Supabase العامة،
  ومحجوب عن دورَي `anon` و`authenticated`. مفتاح موقعك المنشور لا يصل إليه.
- العزل مفروض من جهتين: صلاحيات القاعدة، و`PGOPTIONS` على مستوى الاتصال.
  وسكربت النشر **يتوقف ويُفشل النشر** لو اكتشف أي جدول نظام تسرّب إلى `public`.
- مستخدم النظام `odoo_app` **لا يملك صلاحية الكتابة** في مخطّط `public`،
  فلا يقدر يمسّ جداول نظامك ولا موقعك.
- HTTPS إجباري، والنظام نفسه لا يستمع للإنترنت مباشرة (خلف Caddy على 127.0.0.1).

## نسخة احتياطية

Supabase تأخذ نسخاً يومية تلقائية. ونسخة يدوية وقت ما تبي:

```bash
pg_dump "postgresql://المستخدم:كلمة_المرور@المضيف:5432/postgres" \
  --schema=odoo -Fc -f isystem-$(date +%Y%m%d).dump
```

## ملاحظات

- الملفات والمرفقات تُخزَّن على قرص الخادم في `/opt/isystem/data/filestore`
  (Supabase تحفظ البيانات لا المرفقات) — ضمّنها في نسختك الاحتياطية.
- الباقة المجانية في Supabase توقف المشروع بعد ٧ أيام خمول؛ النظام يتصل باستمرار
  فلن يتوقف ما دام يعمل.
- لو صار النظام بطيئاً، فالسبب غالباً بُعد المسافة بين الخادم وقاعدة Supabase.
  الحل حينها: نقل القاعدة لنفس الخادم (تبقى ملكك بالكامل) — أخبرني وأنفّذها.
