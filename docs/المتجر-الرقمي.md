# المتجر الرقميّ — ibrahimsaud.com/shop/

منتجات رقميّة فقط (حزم، ملفّات، دورات) — بلا شحن. المتجر **غير معلَن**: لا في القائمة
ولا في خريطة الموقع، و`noindex`. يُوصل له بالرابط المباشر.

> `/store/` صفحة «الباقات» (الخدمات) وتبقى كما هي؛ المتجر الرقميّ على `/shop/`.

## الهيكل

| الجزء | المكان | دوره |
|---|---|---|
| الكتالوج والسعر الحقيقيّ | جدول `shop_products` (Supabase) | ما يُخصم فعلاً + الملفّات + التفعيل |
| محتوى الصفحات | `src/lib/shop.ts` | العناوين، ما بالداخل، لمين، الأسئلة، سعر احتياطيّ |
| الصفحات | `src/app/shop/` | الكتالوج `/shop/`، المنتج `/shop/<slug>/`، الطلب `/shop/thanks/` |
| المكوّنات | `src/components/v2/shop/` + `shop.css` | لوحة الشراء، السعر الحيّ، صفحة الطلب |
| الخادم | `supabase/functions/shop/index.ts` | الدفع، الـwebhook، الطلب، الرمز، التنزيل |
| الملفّات | حاوية **خاصّة** `shop-files` | لا تُفتح إلا بروابط موقّعة (٦٠ ثانية) |
| المخطّط | `supabase/shop.sql` | الجداول + RLS + الحاوية + أوّل منتجين |

### مسار الشراء
1. صفحة المنتج تقرأ السعر **حيّاً** من `shop_products` (فما يراه العميل = ما يُخصم).
2. «ادفع» ← `shop` (`checkout`): تقرأ السعر من الجدول (لا من المتصفّح)، تنشئ طلباً،
   وتطلب صفحة دفع من تلر، وتخزّن `order.ref` (مفتاح الفحص — لا `ivp_cart`).
3. تلر تعيد العميل إلى `/shop/thanks/?o=<الطلب>&t=<رمز>&s=ok` وتنادي الـwebhook.
4. الـwebhook وصفحة الطلب كلاهما **يفحصان لدى تلر نفسها** ويطابقان المبلغ، ثمّ
   «مدفوع» مرّة واحدة (idempotent) ← إيميل «طلبك جاهز» برابط ثانٍ مستقلّ.
5. صفحة الطلب: تفاصيل الطلب + الملفّات + زرّ «نزّل» لكلّ ملفّ.

### الأمان (ليش نسخ الرابط ونشره ما يفتح شي)
- **الرمز**: الرابط يحمل رمزاً عشوائيّاً؛ القاعدة تخزّن بصمته (sha256) فقط.
- **ربط الجهاز**: أوّل جهاز يفتح الطلب المدفوع يصير موثّقاً تلقائيّاً (جهاز الدفع
  غالباً). أيّ جهاز آخر يطلب **رمز ٦ أرقام على بريد المشتري** (١٠ دقائق، ٥ محاولات،
  رمز جديد كلّ دقيقة)، حتى **٣ أجهزة**؛ بعدها «راسلني».
- **رابط التنزيل** موقّع ويموت بعد **٦٠ ثانية** — نسخه لا ينفع.
- **سقف التنزيل** لكلّ ملفّ في الطلب (`max_downloads`، الافتراضيّ ١٠)، وكلّ تنزيل
  مسجّل في `shop_downloads` (الوقت، IP، المتصفّح).
- الطلبات والتنزيلات بلا أيّ وصول علنيّ (RLS)؛ المالك يقرأ، والدالّة بمفتاح الخدمة.
- صفحة الطلب `referrer: no-referrer` حتى ما يتسرّب الرمز لأيّ موقع.

المحتوى نفسه بعد تنزيله يقدر صاحبه ينسخه — هذا مقبول؛ المحميّ هو **الرابط**.

## التشغيل لأوّل مرّة (لم يُنفَّذ بعد)
1. **المخطّط**: الصق `supabase/shop.sql` في SQL Editor (جداول + RLS + حاوية `shop-files`
   + أوّل منتجين). ⚠️ الأسعار فيه مبدئيّة: برنامج بث الدروس العلمية **٣٩٩**، والدورة **٣٩٩** (غير مفعّلة).
2. **لا أسرار تلر هنا.** متجر تلر (35146) يقبل طلبات الدفع من عناوين IP مسجّلة فقط
   (لوحة تلر ← Integrations ← Hosted Payment Page ← Authorised IP)، ومنها خادم حروف
   `187.124.119.132`، ودوالّ Supabase بلا IP ثابت. لذلك الدالّة تطلب الإنشاء والفحص من
   `https://huroofduroos.com/api/pay/digital/{create,check}` (ملفّ `routes/pay-proxy.ts` في
   مستودع حروف)، والخادم يقرأ السعر من `shop_products` بنفسه ويفرض روابط العودة.
   `RESEND_API_KEY` و`RESEND_FROM` مضبوطة أصلاً للنشرة البريديّة وتُستعمل هنا.
3. **النشر**:
   ```bash
   supabase functions deploy shop --no-verify-jwt --project-ref rrerwhhxrjyzmnnjsfev
   ```
4. **الإشعار**: Webhook تلر العامّ يشير لخادم حروف (`/api/telr/webhook`)، وهو يمرّر السلّات
   `is-…` لهذه الدالّة (`?action=webhook`) — وهي تفحص لدى تلر بنفسها قبل التسليم.
5. **اختبار**: `DIGITAL_SHOP_TEST_MODE=1` في بيئة خادم حروف يجعل طلبات هذا المتجر وحدها ببطاقة تلر
   التجريبيّة (4111 1111 1111 1111)، ثم يُحذف.
6. **الملفّات**: ارفعها إلى `shop-files` بالمسار المكتوب في `files` (مثلاً
   `lessons-broadcast/BathAlDurus-Setup.exe`)، وحدّث `size_bytes`.

## ⚠️ ملفّات البرامج الكبيرة
مشروع Supabase على الخطّة **المجّانيّة**: أقصى حجم للملفّ الواحد في التخزين **٥٠ ميغا**، ومثبّتات «برنامج بث الدروس العلمية»
٢١٠–٢٦٥ ميغا. الخيارات: Cloudflare R2 (تخزين ١٠ جيجا مجّاناً وتنزيل بلا رسوم، والدالّة تصدر روابط موقّعة S3)،
أو خادم حروف، أو خطّة Supabase Pro (٢٥$/شهر، حدّ ملفّ أكبر). لم يُقرَّر بعد.

## إضافة منتج جديد
1. ارفع الملفّات إلى `shop-files/<sku>/...`.
2. أضف صفّاً في `shop_products`: `sku`, `slug`, `title`, `price_sar`, `files`
   (`[{"id":"…","name":"اسم يظهر للعميل","path":"<sku>/…","size_bytes":…}]`), `active=true`.
3. أضف مدخلاً في `shopItems` بـ`src/lib/shop.ts` بنفس `sku` و`slug` (المحتوى + `fallbackPrice`).
4. ادفع للـmain — تُبنى صفحته `/shop/<slug>/` تلقائيّاً.

تغيير السعر = تعديل `price_sar` في الجدول فقط (الصفحة تقرؤه حيّاً). `fallbackPrice`
يظهر فقط لو تعذّرت القراءة؛ حدّثه ليطابق.

## المعاينة بلا خادم
- `/shop/<slug>/?demo=1` — يُظهر نموذج الشراء حتى لو المنتج غير مفعّل في الجدول.
- `/shop/thanks/?demo=1` — طلب مدفوع وهميّ بملفّين، بلا أيّ اتّصال.

## الربط بالمبيعات والمحاسبة (مكان واحد لكل الدخل)
`public/app/js/26-dshop.js` ← `extSyncStores()`: كل طلب **مدفوع** من المتجر الرقميّ (shop_orders) أو متجر حروف (hrApi admin/store/orders)
يصير «أمر بيع» + «فاتورة» بدفعتها (مصدرها مكتوب: «المتجر الرقميّ — طلب …»)، و`accSyncPayments` يحوّلها قيد دخل:
وحدة «الإنتاج» للمتجر الرقميّ و«حروف ودروس» لمتجر حروف. يُستورد كل طلب مرّة وحدة (`extKey`). يشتغل تلقائيّاً عند فتح
المبيعات أو الفوترة أو المحاسبة أو المتجر الرقميّ (مرّة كل ١٠ دقائق). وضع التجربة (`?demo=1`) لا يكتب شيئاً.
الأسعار تُعامل شاملة الضريبة لو «الفاتورة الضريبيّة» مفعّلة.

## من اللوحة
المالك يقرأ `shop_orders` و`shop_downloads` مباشرة (RLS المالك). إعادة فتح جهاز لعميل:
امسح `trusted_devices` للطلب (`[]`) فيُوثَّق أوّل جهاز يفتحه. زيادة التنزيلات: ارفع
`max_downloads` للمنتج أو احذف سجلّات ذلك الطلب من `shop_downloads`.
